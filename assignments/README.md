# Asignaciones

Cada asignación debe producir una evidencia pequeña, revisable y conectada a una decisión.

| ID | Entrega | Pregunta central |
| --- | --- | --- |
| A01 | Context brief | ¿Qué problema se intenta resolver y para quién? |
| A02 | ADR de almacenamiento | ¿Qué sacrificamos al elegir warehouse, lakehouse o base operacional? |
| A03 | Data quality memo | ¿Podemos confiar en los datos y cómo lo demostraríamos? |
| A04 | BI decision brief | ¿Qué KPI cambia una decisión y cuál solo decora un dashboard? |
| A05 | Plataforma comparativa | ¿Cuándo conviene Snowflake, una alternativa cloud o una solución local? |
| A06 | Visualización | ¿Cómo cambia el diseño según la audiencia y la acción esperada? |
| A07 | ML model card | ¿El modelo es útil, justo, explicable y operable? |
| A08 | Postmortem | ¿Qué aprendimos de una decisión que no funcionó como esperábamos? |

Usar el formato de [`templates/example-repository/docs/adr/ADR-000-template.md`](../templates/example-repository/docs/adr/ADR-000-template.md) para decisiones arquitectónicas.

For capstone projects, use the English [`templates/capstone-example-repository/`](../templates/capstone-example-repository/) template. It adds a standard place for BI dashboards, notebooks, data products, reports, tests, and VS Code/Anaconda configuration.
